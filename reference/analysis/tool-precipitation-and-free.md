## Purpose / pedagogic scenario

A **fixed-scenario speciation-vs-pH plotter**. The student never touches solver parameters: the sweep is hard-wired to **pH 0 → 14 in 501 points, with [H⁺] imposed at equilibrium**. # The chemistry, as an algorithm

Both tools funnel into the same three library calls. Options flow straight through: `Serie.getSolutions(config)` → `helper.setOptions(config)` → `new Equilibrium(model, options)` → `newtonRaphton(..., options)`.

### A. `Helper` — build the system
1. `new Helper()` loads all 125 equations into an `EquationSet`, `solvent: 'H2O'`, auto-adds H₂O with total 0.
2. `addSpecie(label, qty)` per ticked row (accumulates if repeated).
3. `getEquations({filtered: true})` → `EquationSet.getSubset(selectedSpecies)`: transitive closure — pull in every equation whose `formed` is in the set, add its components, recurse (≤10 passes, else "circular dependency"); then repeatedly add any equation *all* of whose components are already present. **This is why ticking `Ag+` + `NH3` silently brings in water autoprotolysis, ammonium, the diammine complex and solid AgOH.**
4. `disableEquation` / `enableEquation` (keyed by `btoa(formed)`) implement the **Ignore/Disabled** checkbox — disabled keys are excluded from `getModel`, and from `getSpecies`/`getComponents` unless `includeDisabled`.
5. `getNormalized(solvent)`:
   - `Equation.withSolvent('H2O')`: an equation whose `formed` is the solvent is inverted (`H2O ⇄ OH- + H+`, pK 14 → `OH- ⇄ -1·H+`, pK −14); H₂O appearing as a component is simply dropped.
   - `normalize()`: any equation whose components are themselves formed elsewhere is recursively substituted (`fillRec`), summing stoichiometry multiplicatively and pK additively, until every equation is expressed on **independent components only**. `NH4+ ⇄ NH3 + H+` (9.25) + `NH3 ⇄ NH2- + H+` (23) ⇒ `NH4+ ⇄ NH2- + 2 H+`, pK 32.25.
6. `getModel()` emits `{volume: 1, components: [{label, total}], formedSpecies: [{label, solid: type==='precipitation', beta: 10**pK, components: [coeffs]}]}`. Components in `atEquilibrium` (set by `setAtEquilibrium`) carry `atEquilibrium` instead of `total`.

### B. `Serie.getSolutions(options)` — the sweep
```
defaults: {chunks: 200, log: false, from: 0, to: 1, isFixed: false}
throw if from >= to, or varying missing
helper = this.helper.clone(); helper.setOptions(options)
for i = 0 .. chunks:
    val     = from + (to - from) * i / chunks
    realVal = log ? 10**(-val) : val
    isFixed ? helper.setAtEquilibrium(varying, realVal)
            : helper.setTotal(varying, realVal)
    eq = helper.getEquilibrium()
    if (previous solution) { eq.setInitial(previous); sol = eq.solve() }
    else                   { sol = eq.solveRobust() }
    sol ? (push val, push sol) : errorCount++
return {x, solutions, errorCount, species: Object.keys(solutions[0])}
```
Continuation: each point warm-starts from the previous one (zeros replaced by 1e-15); a failure resets to a random-restart `solveRobust` (up to `robustMaxTries = 10`) for the following point. **Failed points are dropped from `x` entirely** — the chart is silently shorter, and `errorCount` is the only signal.

For precipitation: `from 0, to 14, log true, isFixed true, varying 'H+'` ⇒ x = pH, [H⁺] imposed = 10^−pH, 501 points.

### C. `Equilibrium` — fold in fixed components
`_processModel` builds the stoichiometric matrix (one row per component, one column per species), separates **solution** species from **solid** ones (`solid: true`), and sets β = 1 for components. For every component with `atEquilibrium`:
> β_new = β_old × [fixed]^(stoichiometric coefficient), then the component is deleted from the optimization.

**This is exactly how "pH imposed" works** — H⁺ never enters the mass balance; it is absorbed into every formation constant. Totals are divided by `volume` (default 1 L), so mol and mol/L coincide. Solid constants are inverted (`solidBeta.pow(-1)`) because the solver works with the dissociation Ksp.

### D. `newtonRaphton` — the solver
Defaults `{tolerance: 1e-15, solidTolerance: 1e-5, maxIterations: 99}` (both views override all three). Per iteration:
1. Compute each solid's ion product Ksp = Π cᵢ^νᵢ. A solid enters the active set if it is supersaturated, or already has a non-zero amount, or is within `tolerance` of saturation.
2. `cSpec = Π c^model · beta` — all species concentrations from component concentrations.
3. `cTotCalc = Σ` over dissolved species + Σ over solids; `d = cTotal − cTotCalc`.
4. Converged when every `|d| < tolerance` **and** every present solid has `|Ksp_target − Ksp_computed| < solidTolerance` → return concentrations.
5. Otherwise build the symmetric Jacobian J* (dissolved block `Σ_l ν_kl ν_jl c_l`, solid block = the solid stoichiometry), solve `Δc = d · J*⁻¹ · diag(c)`, apply it, and **halve the step repeatedly while any concentration would become ≤ 0**.
6. After `maxIterations` → return `null` (counted as an error). Solid amounts are clamped at ≥ 0.

`Equilibrium._processResult` maps the vector back to `{label: concentration}` and re-injects the fixed components at their imposed values — which is why `H+` appears in the output series as a flat 10^−pH line.

### E. `Chart.getChart(x, solutions, {xLabel, yLabel})`
```js
species = Object.keys(y[0]); colors = Color.getDistinctColors(species.length);
per species: {x, y: y.map(s => s[label]), label, xAxis: 0, yAxis: 1,
              defaultStyle: {lineColor: colors[i], lineWidth: 1}}
chart.axis = [{label: xLabel}, {label: yLabel}]
```
`options.xLog` (would map `x → -log10(x)`) exists but **neither view uses it** — both pass the p-scale in already via `Serie`'s own `log` option.
